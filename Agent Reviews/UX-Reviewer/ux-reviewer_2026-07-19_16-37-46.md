# UX Review Report — Oneness Yoga Trainers App

Agent: ux-reviewer
Date/Time: 2026-07-19 16:37:46

Context: Compared against the prior review (`ux-review-13Jul2026.txt`, 2026-07-13). Most previously-reported issues are now confirmed **fixed**: login error message rendering, missing admin Logout, self-deactivation guard, `.list-item` mobile wrapping, form label/id association, Modal focus trap, keyboard access to admin dashboard cards, native `window.confirm()` replaced with `ConfirmDialog`, per-route document titles, favicon, and the router/meta-tag console warnings. New/remaining findings below, most severe first.

| Page/Role | Severity | Issue | Suggested fix |
|---|---|---|---|
| Trainer role — all sub-pages (`TrainerLayout.jsx`) | HIGH | Only the Home/Dashboard page has a visible Logout button (added locally in `pages/trainer/Dashboard.jsx`). `TrainerLayout.jsx` itself has no header at all, so Sessions, Completed, Leaves, Sequences and Resources pages have no way to log out — the user must navigate back to Home first. Reproduced by logging in as trainer1@clowmail.com and visiting `/sessions`, `/leaves`, `/sequences`, `/resources`, `/completed` — no logout control present on any of them. | Add a persistent header (mirroring `AdminLayout`/`SequenceCreatorLayout`) to `TrainerLayout.jsx` with a Logout button, instead of duplicating it only on the Dashboard page. |
| PWA push notifications (`frontend/src/hooks/usePush.js`) | MEDIUM | When `Notification.permission` is already `granted`, the app auto-attempts `pushManager.subscribe()` immediately after `serviceWorker.register()` without waiting for the worker to become active — this throws `AbortError: ... no active Service Worker` on every login (reproduced on every login across all 3 roles, confirmed via console). The failure is silent (console.warn only) — a core PWA feature (session/leave/sequence push updates) silently never works for returning users. | After `navigator.serviceWorker.register()`, await `navigator.serviceWorker.ready` (or listen for `updatefound`/`statechange` to `activated`) before calling `pushManager.subscribe()`. |
| Trainer Dashboard (`pages/trainer/Dashboard.jsx`, lines 54 and 90) | MEDIUM | The "Upcoming Sessions" and "This Week's Sequence" list-item cards are `<div onClick=...>` with `cursor:pointer` but no `role="button"`, `tabIndex`, or keyboard handler (confirmed via DOM query: `tabIndex: -1, role: null`). They are the primary way to drill into a session/sequence from the dashboard and are unreachable by keyboard, unlike the equivalent admin dashboard cards which were fixed to use real `<button>` elements. | Convert to `<button>`/`<Link>` or add `role="button" tabIndex={0}` + Enter/Space handler, matching the fix already applied to `pages/admin/Dashboard.jsx`. |
| Trainer Leaves modal (`pages/trainer/Leaves.jsx`) / Admin equivalents | LOW-MEDIUM | Server validation errors are surfaced verbatim, e.g. submitting From Date after To Date shows the raw backend message "from_date must be before to_date" instead of user-facing copy. Functionally correct (confirmed the validation itself works) but the wording exposes internal field names to end users. | Map known API error codes/messages to friendly copy in `utils/apiError.js` (e.g. "Start date must be before end date"). |
| Add User modal, `pages/admin/Trainers.jsx` | LOW | Submitting the Add User form with empty required fields shows only a red border on the invalid field (Name), with no inline error text/icon — relies on color alone to convey the problem, which is a weak signal for low-vision users and isn't announced to screen readers. Reproduced: opened "+ Add", clicked Save with all fields empty. | Add visible/associated `aria-describedby` error text next to the field (or rely on native browser validation messages consistently), not just a red border. |
| Desktop layout (all roles, 1280px width) | LOW-MEDIUM | The app renders as a single fixed-width mobile layout stretched to fill the full 1280px viewport with no `max-width` container — large expanses of empty space, and the mobile-style fixed bottom tab bar is used at desktop width instead of a sidebar/topbar pattern common for larger screens. Also, on the Admin Dashboard at 1280x800, the last "Manage Resources" quick-link row is initially hidden behind the fixed bottom nav and only becomes visible after scrolling the inner `.page` container (scrollable, but not obviously so — no visible scroll affordance beyond a thin browser-drawn scrollbar). | Add a `max-width` centered container (or a proper responsive desktop layout with a side nav) for viewports above ~768px, and ensure `.page` has enough bottom padding to clear the fixed nav without requiring an undiscoverable scroll. |
| Global (`frontend/src/api/client.js` interceptor area, minor) | LOW | Confirmed fixed for the login-page case, but not re-verified for other 401 scenarios (e.g., session expiring mid-use elsewhere in the app) — worth a follow-up spot check since only the login endpoint was explicitly exercised in this pass. | No action needed unless a repro is found; flagged for awareness only. |

## Verified working well (no issues found)
- Login error state: wrong password now correctly shows "Invalid credentials" inline without a hard redirect (fixed from prior CRITICAL).
- Super Admin Logout button present and working (fixed from prior HIGH).
- Admin Trainers list at 390px no longer overlaps text/buttons; the current admin's own row correctly hides the "Deactivate" action (both fixed from prior HIGH/MEDIUM).
- Form labels now use matching `htmlFor`/`id` across Login, Sessions, Sequences, Leaves forms (fixed from prior MEDIUM, spot-checked in `LoginPage.jsx` and `admin/Sessions.jsx`).
- `Modal.jsx` now implements a real Tab/Shift+Tab focus trap plus Escape-to-close and focus restoration (fixed from prior MEDIUM).
- Destructive actions (Delete Session/Sequence, Mark Complete) use the app's own `ConfirmDialog` component rather than native `window.confirm()` (fixed from prior LOW).
- Per-route `document.title` updates now implemented in `App.jsx` (`usePageTitle` hook) — though note the session/sequence detail routes produce a non-descriptive title like "Oneness Yoga — 2" (numeric ID only) — minor polish opportunity, not filed as a separate issue given low impact.
- Favicon and the `mobile-web-app-capable` meta tag are both present in `index.html` (fixed from prior LOW).
- React Router v7 future flags (`v7_startTransition`, `v7_relativeSplatPath`) are set in `App.jsx` (fixed from prior LOW).
- Bottom nav tap targets measured at ~65x64px — comfortably above minimum touch target guidelines.
- Empty states render clearly across Resources (admin and trainer) and other list pages.
- Sequence Creator role correctly has no bottom navigation, since it has exactly one page (`/sequences`) per the router — not a bug, by design.
