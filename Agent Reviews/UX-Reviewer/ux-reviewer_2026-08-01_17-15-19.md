# UX Reviewer — React 19 Upgrade Regression Smoke Test — 2026-08-01 17:15:19

**Scope:** Narrow regression check confirming the React 18.3.1 → 19.2.8 upgrade (react + react-dom only, no other deps/source changed) did not break the frontend. Not a full UX audit.

**Method:** Automated with a headless Chromium session (Playwright, installed in an isolated scratchpad environment — no project dependencies were modified) driving the real dev servers at http://localhost:5173 (Vite) and http://localhost:3000 (Express/Prisma backend). Console messages, uncaught page errors, and failed requests were captured for every page visited; screenshots taken at 1280px and 390px.

## Environment note (not a React 19 issue)

During testing the backend process was found to have crashed independently, with the log showing:
`Error: Cannot find module '...\node_modules\@prisma\client\runtime\library.js'` (missing generated Prisma client). This caused a transient `500` on `/api/auth/login` mid-session. This is a Prisma/Express-side artifact unrelated to the React version bump (backend and its dependencies were not touched by this upgrade). It was resolved by running `npx prisma generate` and restarting the backend (`npm run dev`), after which the full test suite ran clean. Flagging this so it isn't confused with a frontend regression, and so the dev backend process is verified to actually be running before relying on it.

## Console/error findings

- **No uncaught page errors** (`pageerror` events) on any page throughout the whole flow.
- **No React-19-specific warnings observed** — searched specifically for and found none of: `act()` warnings, hydration warnings, "Cannot update a component (...) while rendering a different component", ref-related warnings, key warnings, "Maximum update depth exceeded", or any other unexpected `Warning: ...` React console output.
- The only console errors seen were pre-existing and unrelated to React:
  - `Failed to load resource: the server responded with a status of 403` and `[GSI_LOGGER]: The given origin is not allowed for the given client ID` — Google Sign-In button failing because `localhost:5173` isn't a registered authorized origin for the configured Google OAuth client ID. Appears on every page load that renders the login screen. Pre-existing OAuth config issue, not caused by the React upgrade.
  - One `[GSI_LOGGER]: google.accounts.id.initialize() is called multiple times` warning, also part of the same pre-existing Google Sign-In component behavior (fires again each time the login screen remounts, e.g., after logout).
  - `Failed to load resource: ... 401 (Unauthorized)` — expected response for the intentional bad-password login test.

## Verdict

No regressions attributable to the React 18 → 19 upgrade were found. All admin routes (Dashboard, Trainers, Sessions, Sequences, Leaves, Resources) render without blank screens or error boundaries, state/forms/modals (including the app's custom focus-trap `Modal` component) behave correctly, login/logout/error states work as expected, and the console is clean of any React-19-flagged warnings. The only notable issue encountered (backend Prisma client missing at process start) is an infrastructure/environment issue unrelated to the frontend dependency bump.
